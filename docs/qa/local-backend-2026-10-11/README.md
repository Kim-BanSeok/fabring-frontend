## 실제 요청과 저장 결과

| 확인 | 결과 |
| --- | --- |
| 모바일 390×844 · 데스크톱 1440×900 | 각 크기에서 BUYER·SELLER 가입/로그인/새로고침/로그아웃 통과 |
| 가입 | 201 × 4, 가입 직후 토큰 없음, 완료 → 로그인 흐름 유지 |
| 로그인 | 200 × 4, 중복 전송 없음 |
| 내 정보 | 로그인·새로고침의 `/users/me` 200 × 8, 같은 계정·Bearer 확인 |
| 필수 동의 | 미동의·하나만 동의 시 제출 불가, HTTP 요청 없음 |
| 중복 가입 / 잘못된 비밀번호 | 각각 409 / 401, 자동 재시도 없음 |
| 로그아웃 | 저장 토큰 제거, 보호 화면에서 로그인 안내 |
| PostgreSQL | 구매자 2명·판매자 2명 저장, 역할 일치, bcrypt 해시 검증 |
| 서버 재시작 | DB·백엔드 종료/재시작 후 health 200, 4계정 보존 |

인증 POST는 정상 가입·로그인 8회와 오류 확인 2회를 합쳐 정확히 10회였다. 폼 비밀번호가 localStorage/sessionStorage에 저장되지 않음을 확인했다. DB 확인은 읽기 전용 조회이며 개발 계정을 삭제하지 않았다. 계정 자격증명은 프론트 폴더 밖 `.local-runtime/auth-accounts.local.json`에만 보관한다. 보고서에는 이메일·비밀번호·토큰을 기록하지 않았다.

## 범위와 다음 단계

이번 실서버 검증은 계정 인증·내 정보 조회와 신규 판매자의 매장 없음 분기를 대상으로 했다. 관리자 계정은 생성하지 않았고, 실제 관리자 로그인·매장 보유 판매자 조회·배포 환경은 확인하지 않았다. 매장 보유 판매자 조회와 복잡한 오류·경합 조건은 [이전 HTTP 계약 검증](../auth-api-2026-10-11/README.md)에 포함되어 있다.

원단·예약·문의·프로필 수정·매장 저장의 실제 연결은 후속 작업이다. 이번 인증 통합 결과만으로 모든 화면의 서버 저장이 완료되었다고 보지 않는다. 기존 전체 시연과 화면 배치는 유지되어 있다.
