## 이번 프론트 연결 범위

| 화면 | 서버 요청 | 표시 기준 |
| --- | --- | --- |
| 구매자 홈 | `GET /fabrics?sale_type=SCRAP&sort=latest&page=0&size=4` | 최근 자투리 최대 4건. 서버가 준 개수만 표시 |
| 원단 목록·검색 | `GET /fabrics` | 자투리/롤 탭, 소재·두께·색상 필터와 페이지 이동. URL의 keyword·sort 조건도 전달·보존 |
| 원단 상세 | `GET /fabrics/{fabricId}` | 실제 상세·사진·매장·구매 가능량 표시 |

홈의 4건은 기존 첫 화면에 맞춘 최신 목록 미리보기입니다. 전체 원단 수나 개인화 추천이 아니며, 롤과 자투리를 섞거나 부족한 개수를 시연 데이터로 채우지 않습니다. 전체 탐색은 목록으로 이어집니다. 별도 홈 집계 API를 요구하지 않습니다.

서버 조회는 공개 API지만 이번 작업에서 로그인 없는 사이트 진입 동선까지 재설계하지 않습니다. 기존 역할별 로그인 이후 구매자 화면으로 가는 흐름과 개발용 시연 진입은 유지합니다. 실제 모드의 조회 실패·빈 목록을 시연 데이터로 대체하지 않으며 시연 모드는 기존 예시를 사용합니다.

**실제 쓰기는 이번 범위 밖입니다.** 원단 등록·수정·사진 업로드, 예약 요청·취소, 문의 작성·답변, 관심 저장과 관리자 처리는 서버 구현 여부와 별개로 각 프론트 화면·오류·재고 갱신을 연결해야 합니다. 목록·상세를 읽을 수 있다는 이유만으로 이러한 동작을 성공 처리하거나 실제 데이터에 대한 시연 처리를 실행하지 않습니다. 추천·도안·공장 목록 등 다른 읽기 기능도 별도 연동 범위입니다.

## 목록10·상세11 계약

기본 주소는 `/api/v1`이고 성공 응답은 `{ success: true, data }`입니다. 식별자는 `fabricId`, `storeId`, `imageId`이며 양의 정수입니다. 그 외 업무 필드는 snake_case입니다.

### 요청과 권한

- 두 API 모두 토큰 없이 조회할 수 있습니다. 다만 Authorization을 보냈는데 토큰이 잘못됐거나 만료됐으면 공개 API도 401입니다. 프론트의 기존 세션 만료 처리를 유지합니다.
- 목록 `sale_type` 기본값은 `SCRAP`이며 `ROLL`과 나눠 조회합니다. `material`, `thickness`, `color_family`는 영문 코드값을 쉼표로 연결합니다. 화면의 한국어 라벨과 요청 코드를 변환합니다.
- 같은 필터의 여러 값은 OR, 서로 다른 필터 조건은 AND입니다. `keyword`는 제목 부분 일치이며 대소문자와 무관하고 `%`, `_`는 문자 그대로 검색합니다.
- 검색어는 trim 후 1~100자입니다. 빈 검색어와 미선택 필터는 쿼리에서 생략합니다. 빈 문자열이나 쉼표 사이 빈 항목을 그대로 보내면 400입니다.
- `sort`는 `latest`, `price_asc`, `price_desc`입니다. 가격이 같으면 최신 등록·ID 내림차순으로 정렬됩니다.
- `page`는 0부터, `size`는 기본20·최대50입니다. 응답은 `content`, `page`, `size`, `totalElements`, `totalPages`이며 결과가 없으면 `totalPages=0`입니다. 범위 밖 페이지의 content는 비어 있습니다.
- 목록은 POSTED만 반환합니다. 구매자·비로그인은 비게시/판매 완료 상세를 404로 받습니다. 본판매자와 ADMIN은 비게시 상태도 조회하지만 삭제 원단은 누구에게나 404입니다.

### 표시 데이터

- 목록은 원단명·판매 형태·단가·소재·두께·색상·치수·구매 가능 길이·예약 여부·하자 여부·대표 사진·매장명을 제공합니다. **매장 주소·storeId·전체 사진·설명은 목록 응답에 없습니다.** 실제 목록 카드에 이 정보를 임의로 보충하지 않습니다.
- 상세 `detail`에는 형태별 치수와 소재·두께·색상·하자·선택 설명 등이, `store`에는 매장명·주소·전화·휴무·픽업 안내가 있습니다. 선택 정보의 null은 미제공 상태로 취급합니다.
- 사진은 `images[]`의 `image_url`, `thumbnail_url`, `image_type`, `sort_order`를 사용합니다. 목록 대표 사진이 없으면 null, 상세 사진이 없으면 빈 배열입니다. 없는 사진을 실제 상품인 것처럼 보이는 예시 이미지로 채우지 않습니다.
- 이미지 URL은 서버에 저장된 절대 URL입니다. 로컬 저장소는 서버 `PUBLIC_URL`을 기준으로 생성하므로 배포 환경에서는 실제 공개 API 주소가 필요합니다. `/api/v1` 등을 이미지 URL 앞에 다시 붙이지 않습니다.
- 자투리는 한 장 전체 가격이며 수락된 예약이 있으면 `is_reserved=true`로 목록에 남습니다. 요청만 있는 경우는 확보된 상태가 아닙니다.
- 롤은 `length_cm=null`, `price`는 90cm당 금액입니다. `available_length_cm`이 구매 가능 길이이고 요청 가능한 최대 마 수는 이를 90으로 나눈 내림값입니다. 롤의 `is_reserved`는 항상 false이므로 구매 가능 여부를 그 값만으로 판단하지 않습니다.
- 상세 `availability`는 구매 가능 길이와 확보 길이를 제공하지만 구매자에게 원시 `remaining_length_cm`을 직접 제공하지는 않습니다. 현재 조회값은 이후 다른 사용자의 처리로 달라질 수 있으며 최종 예약 처리는 서버 재검증이 필요합니다.

## 서버 문서 보완과 프론트 처리의 구분

현재 주요 조회 규칙은 명세·구현·테스트 소스가 일치합니다. 아래 항목은 서버 문서 보완 대상으로 남기며, 프론트에서는 실제 반환값과 공통 계약을 처리합니다.

| 문서의 부족한 부분 | 현재 구현 | 프론트 처리 |
| --- | --- | --- |
| 목록 API 개별 오류 표·OpenAPI에 401 누락 | optionalAuth가 잘못된 토큰에 401 반환 | 기존 인증 오류 처리 적용 |
| OpenAPI의 null 허용이 일부 누락 | 롤 length_cm, 사진·일부 선택 설명 등이 null일 수 있음 | nullable 필드로 처리 |
| keyword 문구에는 최대100자만 명시 | trim 후 최소1자도 검증 | 빈 검색어 생략 |
| 상세 is_reserved 설명의 대상이 모호 | 자투리 ACCEPTED만 true, 롤은 false | 판매 형태별로 예약·재고 표시 |
| 관리자/본판매자 추가 필드 위치가 응답 스키마에 빠짐 | reject_reason, remaining_length_cm을 최상위에 추가 | 구매자 화면의 필수 필드로 요구하지 않음 |

예약 이력·사진 복구·연락처·공장 목록의 후속 상태는 [API 협의 사항](../../API_FOLLOWUPS.md)에 정리했습니다. 특히 예약 응답의 매장 정보 추가는 방문 정보 표시 문제를 일부 해소하지만 예약 시점 주소·가격·치수의 스냅샷을 의미하지 않습니다.

401·로그아웃 후 지연 응답·잘못된 응답 스키마·위험한 사진 URL·요청 취소는 자동 계약/lifecycle 테스트로 검증했습니다. 실제 브라우저에서 강제로401을 주입하지 않았습니다. 다중 사진 정렬은 자동 테스트로 확인했으며 이번 실서버 이미지 업로드·렌더 증거는 사진1장 기준입니다. 이미지 개별 로딩 실패 처리는 코드에 포함했지만 별도의 실서버 재현 증거는 없습니다.

이번 데이터는 실제 판매 상품이 아닙니다. 기존 계정4개를 유지하고 전용 QA 계정2개·가상 매장1개·원단25개(게시 자투리22, 게시 롤2, 미게시1)·예약 상태2건을 별도로 준비했습니다. 원단명·매장명에 `[로컬 검증 20261012]`를 붙였고 재시드의 추가 행은0건입니다. 사진은 업로드 API를 거친 검증용 단색 이미지입니다. 백엔드 소스 변경은 없고 로컬 서버는 다시 실행해 두었습니다.

QA 계정·비밀번호·토큰·DB·서버 환경설정과 로컬 시드 스크립트는 프론트 저장소에 포함하지 않습니다. 이 저장소의 `npm test`는 별도 백엔드 없이 재현할 수 있습니다. 실제 HTTP/브라우저 검증을 다른 PC에서 재현하려면 백엔드 README에 따라 서버와 본인의 테스트 데이터를 준비해야 합니다. 이번에는 기존 개발 DB를 비우는 백엔드 전체 테스트를 실행하지 않았습니다.

예약·문의 전송은 입력 전 미연동 안내를 표시하며 `NOT_CONNECTED` 처리를 유지합니다. 예약·문의 API의 실제 생성·변경은 이번 브라우저 검증 범위가 아닙니다. 배포 환경도 별도 확인이 필요합니다.
