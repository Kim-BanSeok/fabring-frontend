## 화면 흐름 보완

- 문의 작성·조회 후 이전 원단·도안·예약 화면과 검색 조건으로 돌아가도록 복귀 경로를 보존했다.
- 소재 확인이 필요한 추천 결과에서 판매자 문의 화면으로 바로 이동하도록 연결했다.
- 문의 API가 연결됐는데도 미연동이라고 안내하던 추천·대시보드 문구를 현재 동작에 맞췄다.
- 이미 매장을 등록한 판매자에게도 승인 후 매장을 등록하라고 안내하던 관리자 확인 문구를 두 조건이 모두 필요하다는 내용으로 수정했다.
- 복귀 경로는 읽기 전용 구매자 화면과 허용한 검색 조건으로 제한하고, 외부 주소와 잘못된 경로는 제외한다.

## 확인한 결과와 제한

- 롤 원단은 900cm에서 90cm 수령 완료 후 810cm가 남았다. 취소·거절 후 확보 길이는 0cm로 일치했다.
- 자투리 수령 완료 시 경쟁 중인 요청은 서버가 `판매 완료` 사유로 자동 거절한다. 별도로 다시 거절할 필요가 없다.
- API 연속 시나리오에서 제품 코드 수정이 필요한 오류는 발견하지 않았다. 검증 스크립트의 초기 기대값 세 곳은 실제 계약에 맞췄다: 중복 가입 오류 코드 `EMAIL_DUPLICATED`, 원단 목록의 기본 `SCRAP` 판매 형태, 자투리 완료 시 경쟁 요청 자동 거절.
- 실제 AI 모델 품질·요금·키 유효성은 검증하지 않았다. 이번 결과는 개발용 제공자를 통한 대화·저장·사진·승인 연결 검증이다.
- 구매자 전체 문의 모아보기, 문의 본문 수정·삭제는 백엔드 계약이 없어 기존 제한을 유지한다. 이 결과가 해당 API의 구현 완료를 의미하지 않는다.
- 팀 공용 서버, HTTPS, 도메인, 공용 DB와 영구 이미지 저장소에서의 검증은 배포 준비 단계에 속한다. 이 로컬 통합 검증 결과만으로 공용 배포 완료를 의미하지 않는다.

## 데이터와 로컬 환경 보존

- 검증용 DB는 `material_loop_integrated_20261012_test`로 분리했고, 실행 전 `NODE_ENV=test`, 정확한 DB 이름, 루프백 호스트와 포트를 확인했다.
- 백엔드 전체 테스트가 끝난 뒤 시나리오 데이터를 만들었다. 이후 시나리오 진행 중 테이블 초기화는 하지 않았다.
- 브라우저 검증 계정은 API 시나리오 계정과 분리했다.
- 원래 로컬 DB에는 조회만 수행했다. 삭제된 행까지 포함한 11개 모델 전체 행의 SHA256를 작업 전·후 비교했다.
- 계정 비밀번호·토큰·DB 접속정보, 개인용 스크립트와 원본 실행 로그는 커밋 대상에서 제외했다. 이 폴더에는 민감값 없는 요약 증거만 저장했다.
