## A01 · P2 · 전체 원단 지표가 승인 대기 목록으로 연결됨

- 경로/재현: `/admin/dashboard?scenario=123%3A4955&mode=demo` → **등록된 원단수 11 / 전체 등록 원단** 카드 클릭.
- 직접 관찰: `/admin/fabrics?status=PENDING`의 **승인 대기 · 5건**이 열렸다. 상태 선택에는 승인 대기·게시 중·승인 거절·판매 완료만 있고 전체 항목은 없었다.
- 이용자 영향: 카드의 11건 중 나머지 원단이 어디 있는지 알기 어렵고 지표와 목록을 불일치로 받아들일 수 있다.
- 개선: 전체를 보여줄 화면이 준비되어 있으면 연결하고, 현재 상태별 목록만 제공한다면 카드의 링크·설명을 실제 목적지에 맞춘다. 이 관찰만으로 새 전체 조회 API를 필수라고 단정하지 않는다.

## A02 · P2 · 판매자 승인·거절이 한 번의 클릭으로 즉시 확정됨

**먼저 개선할 다섯 항목 중 하나.**

- 경로/재현: `/admin/sellers/seller-1?scenario=123%3A5272&mode=demo` → **판매자 승인**. 새 격리 시나리오에서 같은 상세 → **판매자 승인 거절**.
- 직접 관찰: 확인 단계 없이 각각 **판매자 승인 완료**, **승인 거절** 상태로 즉시 변경되었다. 승인 후에는 처리 버튼이 사라졌다. 원단 게시 승인에는 별도의 최종 확인 화면이 있었다.
- 이용자 영향: 계정 권한을 바꾸는 버튼의 오클릭을 확정 전에 발견할 기회가 없다. 시연에서 실제 피해가 발생한 것은 아니다.
- 개선: 닉네임·매장명·처리 결과를 보여주는 짧은 최종 확인을 넣고, 확정과 취소를 구분한다. 거절 사유 수집은 현재 계약과 팀 정책을 확인한 뒤 별도로 결정한다.

## A03 · P2 · 원단 확인 화면의 ‘검토 화면으로’가 직전 작업 목록을 복구하지 않음

- 경로/재현: `/admin/approvals?id=fabric-pending-2`의 좌측 목록·우측 검토 화면 → **게시글 승인** → `/admin/fabrics/fabric-pending-2?action=approve` → **검토 화면으로**.
- 직접 관찰: 원래의 나란한 목록·검토 화면 대신 `/admin/fabrics/fabric-pending-2` 단독 상세가 열렸다. 사이드바 선택도 **원단 게시 승인**에서 **상품목록**으로 바뀌었다.
- 이용자 영향: 확인만 취소했는데 처리하던 목록과 선택 맥락을 잃는다. 반복 심사에서는 다시 메뉴·대상을 찾아야 한다.
- 개선: 진입한 목록 경로·상태·선택 항목을 기억해 복귀시킨다. 단독 상세에서 들어온 경우에는 현재 복귀 방식이 적절하다.

## A04 · P2 · 게시 결과 미리보기가 구매자 화면으로 전환되며 관리자 복귀 수단이 없음

- 이용자 영향: 관리 중이던 맥락과 역할이 바뀐 것처럼 보여 혼란스럽다. 브라우저 뒤로 가기에 의존하게 된다.

- 한계: 격리 시연의 셸 전환을 확인한 것이며, 실제 서버 권한 우회가 재현된 것은 아니다.

## A05 · P2 · 관리자 사진 검토에 확대·다른 사진 탐색 수단이 보이지 않음

- 경로/재현: `/admin/fabrics/fabric-pending-1` 단독 상세 및 `/admin/approvals?id=fabric-pending-2` 검토 화면.
- 직접 관찰: 각각 큰 단일 이미지 영역만 보였고 전체·상세·하자 사진을 넘기거나 확대하는 버튼이 없었다. 게시 후 구매자 화면에는 이미지 선택 버튼 3개가 있었다.
- 이용자 영향(운영 상황 추론): 실제 원단의 하자·조직·색상을 심사할 때 필요한 근거를 충분히 확인하기 어려울 수 있다. 현재 시연의 대체 이미지 자체를 결함으로 판정한 것은 아니다.
- 개선: 실제 이미지 API 연결 전 관리자에게도 전체·상세·하자 사진 구분, 선택, 확대 보기를 제공한다. 사진이 없을 때는 없음을 명시한다.

## A07 · P3 · 확정 단계에서 대상 정보가 길게 반복되어 핵심 입력과 버튼이 아래로 밀림

- 경로/재현: 원단 상세 → **게시 승인 거절**, 또는 검토 화면 → **게시글 승인**.
- 직접 관찰: 거절 화면은 원단명·판매자·치수·예약 길이·가능 길이 등 9개 정보를 먼저 반복했다. 881px 높이에서 거절 사유 영역 시작이 약 859px로 첫 화면 아래에 걸렸다. 승인 확정 화면도 대상 정보 반복 뒤에 최종 버튼이 배치되었다.
- 이용자 영향: 검토를 마치고 확정하려는 단계에서 다시 긴 내용을 지나야 한다. 특히 거절 사유 작성이라는 주 작업이 바로 보이지 않는다.
- 개선: 최종 단계에서는 원단명·판매자·사진 등 짧은 대상 요약과 효과만 기본 노출하고, 전체 정보는 펼치기로 제공한다. 거절 입력과 최종 행동을 더 앞에 배치한다.

## A10 · P3 · 두 승인 업무의 탭 순서와 선택 스타일이 다름

- 경로/재현: `/admin/sellers`와 `/admin/approvals`를 차례로 확인.
- 직접 관찰: 판매자 탭은 **승인 대기 → 승인 완료 → 승인 거절**, 선택 탭은 진한 녹색 채움이었다. 원단 탭은 **승인 완료 → 승인 대기 → 승인 거절**, 선택 탭은 옅은 배경과 밑줄이었다.

- 개선: 상태 순서를 대기 우선으로 맞추고 선택 표현을 통일한다. 판매자와 원단이라는 업무 구분은 제목·메뉴로 유지한다.
