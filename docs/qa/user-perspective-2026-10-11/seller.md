## S01 · P2 · 문의 작성 중 상태 탭을 바꾸면 초안이 사라짐

**먼저 개선할 다섯 항목 중 하나.**

- 경로: `/seller/inquiries?scenario=123%3A4559&mode=demo`.
- 재현: ‘답변 작성’에 문장 입력 → ‘답변 완료’ 탭 → ‘답변 대기’ 탭으로 복귀.
- 관찰: 경고 없이 빈 입력란으로 돌아온다. 입력한 문장은 복구되지 않았다. 실제 시연으로 재현했다.
- 영향: 다른 답변을 확인하고 돌아오는 자연스러운 왕복에서 작성 내용을 다시 입력해야 한다.
- 개선: 문의 ID별 미전송 초안을 메모리에 유지하고 성공적으로 등록한 뒤에만 지우기. 초안을 유지하지 않는다면 이동 시 이탈 안내가 필요하다.
- 증거: 브라우저 입력값 `찬물로 단독 세탁해 주세요. 제작 전에 작은 조각으로 수축 정도를 먼저 확인해 주세요.` → 복귀 후 접근성 트리 입력값 없음. [seller-inquiry-draft-lost.jpg](screens/seller-inquiry-draft-lost.jpg)는 복귀 상태.

## S02 · P2 · 답변 등록일이 UTC ISO 문자열 그대로 노출됨

## S03 · P2 · AI 화면의 ‘+ 사진 추가’가 전체 직접 입력 화면으로 이동함

- 경로: `/seller/register/ai?type=ROLL` → `/seller/register/manual?type=ROLL`.
- 재현: AI 대화의 오른쪽 ‘정리된 등록 항목’ 아래 ‘+ 사진 추가’ 클릭.
- 관찰: 사진 선택이나 사진 전용 영역이 열리는 대신 ‘원단 등록 · 직접 입력’ 전체 양식으로 전환된다. AI 결과 화면의 ‘사진 추가’와 ‘항목 직접 수정’도 같은 입력 화면을 목적지로 표시한다.
- 영향: AI 작업을 포기하거나 처음부터 다시 입력해야 하는 것처럼 느끼고, 현재 초안이 유지되는지도 확신하기 어렵다.
- 개선: 현재 동작을 유지한다면 ‘사진 추가·내용 보완’처럼 목적지를 예고하고, 이동한 화면에서 ‘AI 초안을 불러왔어요’ 안내와 사진 영역 포커스를 제공한다. 사진 전용 보완 단계도 대안이다.
- 증거: 직접 클릭 후 제목·URL 전환 확인. [seller-ai.jpg](screens/seller-ai.jpg).

## S04 · P2 · 별도 사진 확인 화면의 유일한 다음 행동이 긴 양식으로 돌아가기임

- 경로: `/seller/register/manual?type=ROLL` → `/seller/register/photos?type=ROLL`.
- 재현: 직접 입력 하단 ‘선택한 사진 확인’ → ‘입력 화면으로 돌아가기’.
- 관찰: 선택한 사진 2장이라는 문구와 한 장의 넓은 예시 이미지가 보인다. ‘등록 내용 확인’으로 진행할 수 없고 입력 폼으로만 돌아갈 수 있다. 복귀 시 `scrollY=0`, 폼 문서 높이 약 2362px로 하단 버튼을 다시 찾아야 한다.
- 영향: 최종 확인에 가까워진 사용자가 되돌아간 느낌을 받고 같은 폼을 다시 훑는다. 어떤 사진을 확인한 것인지도 부족하다.
- 개선: 사진별 용도·선택 상태를 보여주고 최종 등록 검토로 계속 진행할 수 있게 한다. 또는 사진 확인을 현재 폼 안에서 열어 스크롤 위치를 유지한다.

## S05 · P2 · 미선택 사진 슬롯과 선택된 슬롯의 큰 이미지 표현이 같음

- 경로: `/seller/register/manual?type=ROLL`.
- 재현: 사진이 2장 선택된 예시 또는 AI에서 사진 추가를 눌러 사진이 없는 입력 상태 확인.
- 관찰: 하자 사진이 선택되지 않았어도 커다란 원단 질감 이미지가 채워져 있다. 선택 여부는 아래 작은 ‘선택한 사진 없음 · 위 이미지는 예시’와 버튼 문구로만 구분된다. 최종 검토에도 미선택 하자 사진 예시가 나타난다.
- 영향: 빠르게 훑으면 3장이 모두 등록된 것처럼 오인할 수 있다.
- 개선: 미선택 슬롯은 빈 업로드 상태, 선택된 슬롯은 선택 상태로 명확히 구분한다. 실제 이미지 연동 전 예시를 유지하더라도 ‘예시’ 표시는 이미지 위에 명확히 두고, 미선택 예시는 최종 검토에서 제외한다.
- 제한: 실제 파일 업로드를 하지 않았으므로 실제 파일 미리보기 동작 자체에 대한 결함 판정은 아니다.
- 증거: [seller-manual-photos.jpg](screens/seller-manual-photos.jpg).

## S06 · P2 · 부분 업로드 실패 화면에 실패한 사진이나 완료 개수가 없음

- 경로: `/seller/upload?scenario=210%3A8628&mode=demo`.
- 재현: 상태 목록의 ‘일부 사진 업로드 실패’ 예시 진입 → 안내 확인 → 재시도.
- 관찰: ‘일부 사진’, ‘이미 올라간 사진’이라는 안내와 재시도 버튼만 있다. 어떤 원단의 몇 장 중 무엇이 실패했는지 표시되지 않는다. 재시도는 정상 완료됐다.
- 영향: 사용자가 무엇을 복구하는지 알기 어렵고, 목록 확인으로 떠나도 되는지 판단하기 어렵다.
- 개선: 대상 원단명과 사진별 파일명/용도·성공/실패 상태, 예를 들어 ‘2장 중 1장 완료’를 표시한다. 기존의 ‘새 원단을 만들지 않고 실패 사진만 재시도’ 정책은 유지한다.
- 증거: [seller-upload-partial.jpg](screens/seller-upload-partial.jpg).

- 경로: `/seller/calendar?month=2026-10&date=2026-10-15`.
- 재현: 예약 수락 후 홈 → 월별 픽업 일정 보기 → 예약 없는 15일 클릭 → 아래 결과 확인.
- 관찰: 날짜 클릭으로 목록은 필터링되지만 선택 셀의 지속적인 강조가 없다. 결과는 ‘10월 선택한 날짜에는 등록된 픽업 일정이 없어요.’로 표시되며 ‘15일’은 없다.

- 개선: 선택 셀에 색/테두리와 접근성 선택 상태를 유지하고 ‘10월 15일 · 픽업 0건’처럼 구체적인 제목을 표시한다. 날짜 클릭 시 페이지 최상단으로 돌아가지 않도록 현재 달력 위치도 유지하는 편이 좋다.

## S13 · P3 · 이미 등록된 매장 수정 화면에도 신규 가입용 문구가 남음

- 경로: `/seller/profile` → ‘매장 정보 전체 수정’ → `/seller/store`.
- 관찰: 승인 완료·매장 등록 완료인 상태에서도 ‘운영팀의 판매자 승인이 완료되면 원단을 등록할 수 있어요’가 표시된다. 뒤로 이동 버튼은 ‘나중에 입력’이다.
- 영향: 기존 정보 수정인지 최초 등록 준비인지 맥락이 불분명해진다. ‘나중에 입력’이 수정 내용을 보류 저장하는 것처럼 해석될 수도 있다.
- 개선: 최초 등록이면 현재 안내를 쓰고, 기존 수정이면 ‘수정 취소/마이페이지로’ 등 현재 맥락에 맞춰 제목·보조 문구·복귀 목적지를 바꾼다.
