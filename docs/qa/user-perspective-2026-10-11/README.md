# 양주 섬유 루프 · 이용자 관점 UX/UI 검토

검토 2026-10-11~12 (KST) · React 작업본 `7b99e5a` · 실제 구동 화면 기준

전체적인 녹색·아이보리 색감과 역할별 구조는 일관적이다. 현재 가장 큰 개선 여지는 장식보다 **이용자가 다음 행동을 찾는 순서, 입력 내용 보존, 구매·방문·승인에 필요한 정보의 위치**에 있다. 모바일에서는 데스크톱 구성요소를 세로로 쌓은 결과 메뉴·필터·사진이 실제 작업보다 앞을 오래 차지한다.

**개선 항목 52개: 공통 8 · 모바일 6 · 구매자 12 · 판매자 14 · 관리자 12.** P2 37개, P3 15개다. 52개의 서로 독립적인 버그라는 의미는 아니며, 공통 원인과 화면별 적용 지점을 연결해 적었다. 심각도는 실제 이용 영향에 대한 검토자의 판단이다. 전면 개편이나 기능 확대를 전제로 하지 않는다.

## 검토 방법과 범위

| 범위 | 실제 확인한 흐름 |
|---|---|
| 구매자 | 홈→원단 목록→조건 검색/취소→상세→문의 작성/복귀→픽업 입력, 수락·취소 확인 예시, 활용 아이디어→제작 조건→도안→부자재→복귀 |
| 판매자 | 대시보드→직접 등록→사진 확인→최종 검토→신청 완료, AI 초안/사진 보완, 사진 부분 실패→재시도, 예약 수락→달력, 문의 초안/등록, 프로필·매장·승인 거절 |
| 관리자 | 대시보드→판매자 목록/승인/거절, 원단 목록/필터→검토→확정/취소→결과→게시 미리보기, 거절 사유·오류 복구·빈 상태 |
| 공통·모바일 | 실제 계정 모드의 빈 로그인/가입 양식, 키보드 본문 건너뛰기, 구매자 홈/목록/상세/픽업, 판매자 등록/표/프로필, 관리자 대시보드/검토 |

- 데스크톱은 약 1339~1354×881~937 및 1440×900, 모바일은 브라우저 390×844, 좁은 가입 화면은 320×780에서 확인했다. 모든 화면을 모든 크기로 검증한 것은 아니다. 좌표는 해당 화면·시연 데이터에서 측정한 대략적인 CSS 픽셀이다.
- 거래·승인·문의 상태 변경은 격리된 시연 메모리에서 확인했다. 실제 운영 데이터는 변경하지 않았다. 구매자의 최종 예약·문의 제출과 취소 실행은 하지 않았다. 제출 결과는 별도 예시로 확인했다.
- 이번 검토는 실제 회원가입/로그인 API 재검증, 실제 이미지 업로드, 실제 AI 결과 품질, 모든 경로의 회귀 테스트, 실물 휴대폰/Safari/가상 키보드/스크린리더 전체 감사가 아니다. 업무 API 미연동 그 자체는 신규 결함으로 집계하지 않았다.
- 화면 관찰과 이용 영향에 대한 해석을 구분했다. C08은 파일 크기 기반 성능 검증 후보이고, A05/A06/A11의 운영 영향은 추론이다. 실제 사용자 조사나 사용성 실험 결과는 아니다.
- `scenario` 식별자는 검토 당시의 시연 문맥이다. 재현할 때 화면 모음에서 같은 상태 예시로 진입한다. 특정 식별자가 새 세션에서도 계속 유효하다고 보장하지 않는다.
- 요청에 따라 피드백과 증거만 정리했다. 이번 검토로 앱 코드·Figma·백엔드를 수정하거나 커밋·푸시하지 않았다.

## 폰트·색감·배치 기준 제안

| 항목 | 현재 관찰 | 권장 방향 |
|---|---|---|
| 글꼴·크기 | Noto Sans KR는 일관적이나 본문 14px, 중요 도움말도 12px | 글꼴은 유지, 본문/입력 16px·핵심 메타 14px를 시작점으로 실제 화면 확인 |
| 색감 | 녹색·아이보리의 브랜드 통일성은 좋음 | 팔레트 전체 변경보다 안내 글자·입력 경계·상태 배지 대비 보정 |
| 텍스트 대비 | placeholder 약 2.92:1, 캔버스 위 공통 안내 약 4.47:1 | 일반 크기 텍스트 4.5:1 이상 검증. C02의 조합·측정 범위 참고 |
| 입력 경계 | 흰 배경/활성 테두리 약 1.47:1 | 컨트롤을 식별하는 필수 경계는 3:1 기준 점검. 장식 구분선은 구별 |
| 버튼 위계 | 일부 완료 화면에 같은 버튼이 여러 개, 수락 예약엔 취소만 강조 | 화면의 주 행동 하나를 먼저 보이게 하고 취소·다른 이동은 보조로 |
| 모바일 정보 순서 | 헤더·필터·큰 사진 다음에 상품/가격/입력/처리 | 이용자가 판단할 정보와 행동을 먼저. 모든 것을 첫 화면에 억지로 압축하지 않기 |
| 간격·구도 | 관리자 확정/결과는 같은 정보가 반복되고 큰 필터 패널이 있음 | 반복 요약은 합치고 입력·결과·다음 업무를 한 묶음으로 배치 |
| 표·정렬 | 판매자 표가 모바일 컨테이너보다 약 3배 넓음 | 모바일 행/카드 안에 상태·수량·주 행동 표시. 숫자·단위의 읽는 순서 통일 |
| 선택 상태 | 달력 선택일 표시 약함, 승인 업무 탭 순서/모양 다름 | 요일·상태 순서·선택 표현을 공통 규칙으로 정리 |

본문 크기는 디자인 권장치다. 접근성 대비의 근거는 [W3C 일반 텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [W3C 비텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)다. 특정 색 조합의 측정이며 사이트 전체 WCAG 준수 여부를 판정하지 않았다.

## 작업을 묶는 순서

1. **입력·판단·복귀:** 먼저 개선할 다섯 개와 필터 취소 B03, 관리자 복귀 A03/A04를 묶는다.
2. **공통 스타일·모바일:** C01~C04와 M01~M06. 필터 조정 때 B04/B05, 등록 높이 조정 때 S04/S05도 함께 확인한다.
3. **역할별 정보 연결:** B06~B10, S02/S06/S07/S09/S11, A01/A05/A06. 기존 기능의 의미와 연결을 맞춘다.
4. **일관성과 마무리:** 남은 P3, 시연 이미지 정합성, 공개 첫 진입 C07. C08은 측정 후 최적화 여부를 결정한다.

프론트에서 바로 고칠 수 있는 것은 위치·라벨·버튼 위계·초안 보존·복귀·날짜 표시다. 다음은 계약/정책 확인이 필요하다.

- B01/B07: 조회 가능한 매장·픽업 정보 범위와 예약 당시 주소를 보존할지 여부.
- C05: 실제 사용할 약관·개인정보 처리방침 문안.
- S10: 판매자 승인 거절 후 문의·재검토 절차.
- A05/S06: 실제 사진 목록·용도·파일별 성공/실패 데이터를 어떻게 받는지.
- A06/A11: 목록에 노출 가능한 매장 식별 정보, AI 생성·판매자 확인 상태가 실제로 존재하는지.

없는 데이터·새 기능을 화면에서 약속하지 말고 현재 계약으로 가능한 표시와 팀 합의가 필요한 부분을 나눠 진행한다.

## 유지할 점

- 이전 관리자 로그아웃 문제는 재현되지 않았다. 확인한 데스크톱 위치에서 버튼 아래 여백 24px로 하단에 유지됐다. 정상적인 안쪽 여백을 오류로 보지 않는다.
- 녹색·아이보리 톤, 구매자/판매자/관리자 업무 구분, 기본 버튼 48px와 탭 44px은 유지할 만하다.
- 구매자 문의 초안의 뒤로 가기 복구, 검색 상세에서 검색 조건 복귀, 부자재에서 원래 도안으로 복귀는 확인됐다.
- 관리자 거절 사유의 필수 입력·초점 이동·작성 내용 유지, 상태 처리 후 대기 건수 감소는 시연에서 정상 동작했다.
- 판매자의 사진 부분 실패 재시도와 확보/수령 차감의 구분 안내는 유지할 가치가 있다.
- 본문 건너뛰기 링크는 가입 화면에서 작동했다. 320px 가입 화면에서도 페이지 전체 가로 넘침은 확인되지 않았다.
