# 문의·개인 프로필 API 연동 검증

2026-10-12 · 백엔드 main `7dc28c79994295daee635524d05048574247a6d9`

## 연결 범위

- 42 `POST /fabrics/:fabricId/inquiries`: 구매자의 공개/비공개 문의 작성.
- 43 `GET /fabrics/:fabricId/inquiries`: 원단별 문의·답변과 페이지 조회, 서버가 적용한 비공개 가림.
- 44 `GET /sellers/me/inquiries`: 판매자가 받은 문의의 전체/WAITING/ANSWERED 조회.
- 45 `POST /inquiries/:inquiryId/answer`: 본인 매장 원단 문의의 답변과 기존 답변 수정.
- 3·4 `GET/PATCH /users/me`: 구매자·판매자의 닉네임과 개인 연락처 조회·저장, 빈 연락처 삭제와 현재 세션 반영.

기존 원단 문의, 판매자 문의함, 프로필 배치와 이동 흐름을 유지했습니다. 이메일·역할·비밀번호 수정, 매장 전화 수정, 예약 연락처 전달은 개인 프로필 저장에 포함하지 않습니다. 관리자 프로필 PATCH는 서버/adapter 계약 검증 대상으로만 확인하며 새 관리자 편집 화면은 추가하지 않습니다.

## 데이터를 섞지 않는 검증 환경

기존 개발 DB에 로컬 테스트 데이터가 계속 쌓이지 않도록 **이번 작업만을 위한 별도 PostgreSQL 테스트 DB**를 만들었습니다. 실행 전 NODE_ENV=test·정확한 DB 이름·127.0.0.1·DB 포트를 검사한 뒤 마이그레이션과 테스트를 실행했습니다. 기존 개발 DB와 이전 공용 테스트 DB에는 reset/fixture/PATCH/POST를 실행하지 않습니다.

수정하지 않은 백엔드 Express 앱을 루프백 포트3002로 실행하고, 별도 Vite 포트5174를 이 서버에 연결했습니다. 기존5173 화면의 환경 파일과 API 프록시는 유지합니다. 검증 계정·랜덤 비밀번호·DB 설정·개인 실행 스크립트는 프론트 저장소에 넣지 않습니다. 이 폴더에는 비밀값 없는 결과와 합성 데이터 화면만 저장합니다.

## 실제 React 화면 검증

전용 합성 계정으로 다음 흐름을 직접 클릭했습니다.

1. 구매자 프로필 닉네임·연락처 저장 → 다시 수정하여 연락처 비움 → null 저장 확인.
2. 게시된 원단에서 공개·비공개 문의를 각각 작성 → 실제 목록의2건과 완료 표시 확인.
3. 문의 내역에서 이번 탭의 원단 바로가기 확인. 이 목록을 전체 본인 문의 내역으로 표시하지 않는 안내 확인.

## 계약의 한계와 남은 작업

- 구매자가 모든 원단에 작성한 문의를 모아 보는 API는 현재 없습니다. 일부 원단의 문의를 전체 내역으로 표시하거나 닉네임을 비교해 작성자를 추정하지 않습니다.
- 문의 본문 수정·삭제46~47은 명세에 있으나 현재 routes에서 확인되지 않습니다. 판매자가 답변을 고치는45의 동작과 구분합니다.
- 비공개 응답에는 명시적 canRead나 작성자ID가 없습니다. 서버 가림 문자열과 null 답변을 그대로 보여주며 누락 내용을 임의로 복원하지 않습니다.
- 문의 생성은 멱등성 키가 없습니다. 응답 유실 뒤 목록에서 비슷한 글을 찾거나 한 번의 조회에 안 보인다는 이유로 생성 결과를 확정하지 않습니다.
- 개인 연락처를 저장해도 판매자 예약 화면으로 구매자 연락처가 전달되는 계약은 생기지 않습니다. 이메일·비밀번호 변경도 별도입니다.
- 문의·프로필 연결 완료와 공용 배포 완료는 다릅니다. 관심 저장·지도는 별도 선택 범위이며 약관, 실제 AI 실행/이력, 게시 후 비공개 등 계약·정책 항목은 [연결 현황](../../INTEGRATION_STATUS.md)에 남습니다.
