# 관리자 판매자·원단 관리 API 연동

2026-10-12 · 독립 계약 검토 기준 `7dc28c79994295daee635524d05048574247a6d9`

**구현과 로컬 검증을 완료했습니다.** 기존 화면 배치와 흐름을 유지하여 관리자 목록·상세·상태별 통계, 판매자 승인/거절, 원단 게시 승인/반려를 연결했습니다. [연결 현황의 M3](../../INTEGRATION_STATUS.md#core-work)에 해당합니다. 전체 테스트275개·lint·build, 실제 HTTP119개·live adapter27개, 브라우저 처리와 최종 읽기 전용 GET/DB 확인26개를 통과했습니다. 앱 번들608.21kB 경고는 남습니다.

계약 검토는 [명세33~38][api], 관리자 routes·validator·service·DAO와 기존 테스트 정의를 대조했습니다. 아래의 계약 확인을 이번 실행 결과로 세지 않습니다. 계정·매장·원단·예약의 이전 QA는 당시 결과를 유지합니다.

## 연결 대상

기본 주소는 `/api/v1`이며 모든 `/admin` 경로는 ADMIN 인증이 필요합니다. 승인 요청은 프론트에서 확인 화면을 거쳐 보내며 서버가 현재 상태를 다시 검사합니다.

401 인증·403 역할·404 대상 없음·409 상태 변경을 구분합니다. 원단 승인에 사진이 없으면400 `IMAGE_REQUIRED`입니다. 없는/삭제된 원단, 판매자가 아닌 회원·탈퇴 회원에 대한 처리에는404 `NOT_FOUND`를 반환합니다. 원단과 판매자 상태 변경은 트랜잭션과 행 잠금으로 처리하며, 이미 처리된 승인을 다시 보내면409입니다.

판매자 승인 API에는 매장 존재 조건이 없습니다. 매장이 없는 판매자도 승인할 수 있지만 이후 원단 등록에는 승인과 매장이 모두 필요합니다. 판매자 거절 사유·재신청 API는 없으며 거절된 판매자는 운영팀이37번으로 승인할 수 있습니다. 원단 반려 사유와 판매자 거절을 같은 입력 계약으로 취급하지 않습니다.

## 목록·페이지·통계

원단 status는 PENDING/POSTED/REJECTED/SOLD_OUT, 판매자는 PENDING/APPROVED/REJECTED입니다. 둘 다 생략하면 PENDING이며 `ALL`은 지원하지 않습니다. page는0부터, size는 기본20·최대50입니다. 정렬은 생성 시각 오름차순, 같은 시각에는 식별자 오름차순으로 오래 기다린 항목부터 보여 줍니다. 별도 검색어·정렬·판매 형태 필터를 서버 지원 기능으로 표시하지 않습니다.

응답은 `content`, `page`, `size`, `totalElements`, `totalPages`입니다. 삭제된 원단과 탈퇴한 판매자는 제외됩니다. 원단 사진 수가 많아도 목록 건수는 원단 수이며 사진은 `sort_order` 순으로 반환합니다.

상태별 통계는 기존 목록 응답의 `totalElements`를 사용합니다. 원단4개 상태·판매자3개 상태의7개 요청으로 집계하며, 한 페이지 행 수를 전체 건수로 쓰지 않습니다. 여러 응답 시점의 합계로 단일 시점 스냅샷이 아닙니다. 조회 실패를0건으로 표시하거나 일부 상태 합계를 전체 합계로 표시하지 않습니다. 월별 신규 가입·전체 구매자 수 등 이 계약으로 얻지 못하는 예시 통계는 실제 통계로 만들지 않습니다.

## 목록과 선택 상세의 차이

관리자 전용 판매자·원단 GET 상세 경로는 없습니다. 판매자 선택 정보는 상태별 목록에 포함된 회원·매장 정보로 구성합니다. 직접 링크·새로고침 때는 전달받은 상태를 먼저 확인하고 나머지 상태의 페이지를 탐색합니다. 페이지당50명, 모든 상태를 합해 최대200페이지를 조회하며 상한 초과는 `LOOKUP_LIMIT` 오류로 구분합니다. 중간 페이지 실패·정합성 오류를 대상 없음으로 바꾸지 않습니다. 끝까지 찾지 못한 경우에도 조회 중 상태가 바뀌었을 가능성과 목록 재확인을 안내합니다. 서버 목록 순서와 상태가 탐색 중 바뀔 수 있어 단일 시점의 단건 조회와 같지는 않습니다.

판매자 목록은 `userId`, 이메일·닉네임·nullable 개인 전화번호, `seller_approval_status`, `created_at`, 매장 DTO를 포함합니다. 매장 미등록이면 `store:null`이며 정상 데이터입니다. 회원 비밀번호·거절 사유는 포함하지 않습니다. 매장 DTO의 휴무일·픽업 안내도 null일 수 있습니다.

관리자 원단 목록은 `fabricId`, 제목·판매 형태·가격·실제 남은 길이·상태·매장 이름·detail·images·생성 시각을 제공합니다. `reject_reason`, `reserved_length_cm`, `available_length_cm`, 자투리 예약 여부와 매장 번호·주소·전화는 없습니다. 목록의 롤 잔량을 가용 길이로 바꾸거나 없는 예약값을0으로 채우지 않습니다. 사진 배열은 비어 있을 수 있고 매장 이름과 detail도 누락 가능성을 고려해야 합니다.

원단 선택·상세는 기존 일반 원단 상세11을 ADMIN 토큰으로 호출합니다. PENDING·POSTED·REJECTED·SOLD_OUT을 조회할 수 있고, 최상위 `reject_reason`, `remaining_length_cm`과 `availability`, 전체 매장 DTO를 반환하므로 목록에 없는 정보를 기존 계약으로 확인합니다. 삭제 원단과 원단 detail이 없는 대상은404입니다. 원단 공개 여부만 보고 관리자 조회가 불가능하다고 판단하지 않습니다.

## 처리 결과와 복구

- 원단 승인·반려와 판매자 승인·거절 모두 대상 이름·현재 상태를 확인하고 요청합니다. 액션 중복 클릭을 막고 페이지 이탈·계정 변경 뒤 늦은 응답이 다른 화면을 이동시키지 않습니다.
- 성공200의 식별자·상태를 먼저 보존합니다. 뒤이어 상세·목록·통계 조회가 실패해도 처리 자체가 실패했다고 안내하거나 같은 POST를 다시 보내지 않습니다.
- 응답 유실·시간 초과·확인할 수 없는 응답은 결과 불명으로 다룹니다.409도 기존 상태가 달라졌다는 뜻이므로 최신 서버 상태를 먼저 확인합니다. 자동 재전송이나 낙관적 승인 완료로 대체하지 않습니다.
- 반려 입력은 성공 응답 전까지 초안을 보존하고 계정·대상 간에 섞지 않습니다. 요청 직전에 최신 정보와 검토한 내용을 비교하여 상태·사진·입력 내용이 바뀌었으면 재검토를 요구합니다. 반려 후 판매자가 보완해 다시 PENDING이 된 원단도 과거 성공 기록에 막히지 않고 재심사할 수 있습니다.
- 목록·처리 확인·선택 상세 사이를 이동할 때 상태·페이지와 돌아갈 경로를 보존합니다. 마지막 행이 처리되어 페이지가 비면 서버 total을 기준으로 첫 페이지·목록 복귀를 안내합니다.

## 브라우저 확인

- 전용 판매자 두 계정의 승인·거절과 결과 화면을 확인했습니다.
- 사진이 있는 원단을 게시 승인한 뒤 실제 구매자 홈과 상세에 나타나는 것을 확인했습니다. 다른 원단은 반려 사유를 입력해 저장했고 새로고침 후 현재 상태와 사유가 복원됐습니다.
- 반려 사유는 검토 화면을 왕복해도 유지되고 최대255자입니다. 사진이 없는 원단은 승인 확정 버튼을 비활성화합니다.
- 게시 중 상품 목록의 page=1, size=2에서 상세를 열었다 돌아와도 상태와 페이지가 유지됐습니다.
- 모바일390×844에서 문서 폭375px와 스크롤 폭375px로 가로 넘침이 없었습니다. 승인 카드 버튼은 기존 짧은 문구로 유지했습니다. 검증 중 콘솔 오류·경고는 없었습니다.
- 완료 응답이 없는 직접 결과 URL이나 새로고침은 현재 상태 조회로 표시하며 새 승인 성공을 주장하지 않습니다.
- 응답 불명·로그아웃·중복 제출·변경된 내용·이전 성공 이후 재신청·쓰기와 겹친 조회 무효화는 클라이언트 모의 테스트로 검증했습니다. 서버가 무효화한 조회는 재조회 가능한 오류로 표시하여 무한 로딩을 막습니다. 네트워크 응답 유실을 실서버에서 강제로 재현한 결과는 아닙니다.

## 이번 범위 밖의 계약

POSTED 원단을 비공개로 바꾸는 처리와 진행 예약 영향은 아직 계약이 없습니다. 관리자 PENDING 승인/반려 연결만으로 요구사항 ADMIN-02를 충족했다고 보고하지 않습니다. 관리자 구매자 조회·상태 외 검색·전용 통계·대량 데이터용 판매자 단건 조회는 별도 요구와 규모에 따라 협의하며, 기본 상태별 건수를 위해 새 통계 API가 선행 필수라고 요청하지 않습니다. 실제 도안 추천 M4·AI 보조 등록 M5와 통합·배포 마무리도 별도입니다.
