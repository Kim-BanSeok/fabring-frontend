# 인증 화면 최종 UX 수정 확인

사용자 승인 후 `pages/auth.js`, `pages/auth.css`만 수정했습니다. Figma 원본과 React 코드는 수정하지 않았습니다. 공통 라우터의 replace 옵션과 미리보기 도구 문서 하단 배치는 root 작업입니다.

## 확인한 문제와 수정

1. 390×844 화면에서 소개 카드가 398~466px를 차지해 로그인 버튼이 첫 화면 아래로 밀렸습니다. 모바일 소개를 102~136px로 줄이고 긴 본문과 장식 질감을 숨겼습니다. 한국어 단어는 나누지 않습니다. 데스크톱의 572px 열, 720px 소개 카드, 28×28 로고는 유지했습니다.
2. 로그인 성공·실패 뒤 브라우저 뒤로가기가 이미 종료된 processing 경로로 돌아가 멈췄습니다. 결과 이동은 라우터의 replace 옵션을 사용합니다. 성공 뒤 입력 화면으로 돌아왔을 때 비밀번호는 비어 있고, 실패 뒤에는 입력을 복구합니다.
3. 처리 경로를 직접 열거나 처리 중 새로고침한 경우 재시작 안내와 복구 버튼을 제공합니다. 명시적인 상태 갤러리는 진행 중 화면을 유지하고 돌아가기 버튼을 제공합니다.

## 검증 결과

- 로그인 버튼 하단: 구매자 910→590px, 판매자 954→624px, 관리자 886→590px. 모두 390×844 첫 화면 안에 있습니다.
- 390px·1440px의 3역할 로그인 성공/뒤로가기, 실패/입력 유지, 약관 각각의 disabled 상태, 가입 불일치 오류 복구와 완료 뒤로가기를 실제 클릭했습니다.
- 판매자 첫 로그인→매장 정보→브라우저 뒤로가기, 처리 중 새로고침, 직접 처리 화면, 갤러리 처리 화면의 복구 동작을 확인했습니다.
- 공통 미리보기 도구가 열린 상태에서도 인증 폼과 겹치는 면적은 0입니다.
- 검증 범위 가로 넘침 0, 브라우저 실행 오류 0, 비밀번호 영구 저장 없음. 실제 인증 서버는 호출하지 않습니다.
- 대표 수정 전·후 이미지를 직접 비교했습니다. 마지막 한국어 줄바꿈 조정 뒤 모바일 3역할 버튼 위치와 이미지를 다시 확인했습니다.

`inspection.json`은 수정 전, `regression-after.json`은 수정 후 검증입니다. `regression.mjs`로 같은 범위를 재현할 수 있습니다. 공유 개발 서버 편집에 따른 자동 새로고침이 인증 처리 중 끼어들지 않도록 QA 브라우저의 Vite WebSocket만 차단했습니다. 앱 코드는 바꾸지 않았습니다.
