# 판매자 실제 배치 점검 — 2026-10-11

React 개발 서버의 격리된 브라우저 컨텍스트에서 전체 viewport를 캡처했다. 기존 HTML과의 일치가 아니라, 보이는 여백·정보 위계·버튼 정렬을 기준으로 판단했다. Figma 원본과 서비스/상태 전이 로직은 변경하지 않았다.

## 반영

| 확인한 문제 | 조정 |
| --- | --- |
| 승인 안내의 최소 높이 595px / 모바일 500px가 제목과 버튼을 아래로 밀음 | 강제 높이·중앙정렬을 제거하고 다른 판매자 화면과 같은 상단 정렬 |
| 사진 실패 화면의 viewport 높이 중앙정렬로 모바일 상단이 비어 있음 | 콘텐츠 기준 높이와 상단 padding으로 변경 |
| 등록방법 카드 설명 아래 빈 spacer | 빈 요소 제거, 카드 CTA의 정렬 유지 |
| 등록 검토 사진이 정보 카드보다 지나치게 큼 | 대표/보조 사진 340/140px, 모바일 200/88px로 조정 |
| 대시보드 달력 링크가 단독 전체 너비 행을 차지 | 픽업 일정 카드 제목 옆으로 이동 |
| 모바일 상태 필터의 불규칙한 줄바꿈 | 가용 폭에 맞춘 동일 너비 열 배치 |
| 완료 예약의 단독 재고 버튼이 2열 중 한 칸만 차지 | 해당 단독 버튼을 액션 영역 너비에 맞춤 |
| 월별 달력에서 날짜+픽업 문구가 4줄로 꺾이며 해당 주만 늘어남 | 날짜/픽업 건수를 별도 줄로 표시. 모바일은 건수만 표시하고 접근성 이름에 날짜·픽업 건수 보존. 날짜 셀 높이 통일 |
| 320px 월 이동 버튼이 2+1로 배치됨 | 기존 버튼 3개를 동일 너비 한 행으로 배치 |

제목의 한국어 단어 줄바꿈과 업로드 완료 요약의 데스크톱 2열 배치도 정리했다. 길이가 필요한 입력 폼과 상세 콘텐츠는 자연스럽게 스크롤되도록 유지했다.

## 검증

- 기본 10개 화면 × 4개 viewport(1440×900, 1366×600, 390×844, 320×844): before 40장, after 40장, JavaScript 오류 0 / 가로 넘침 0.
- 추가 판매형태·AI 결과·AI 오류·삭제 확인·달력·매장 화면 12장: 가로 넘침 0. 캡처를 직접 열어 여백과 줄바꿈을 확인했다.
- 실제 클릭 8개 그룹: 달력 이동, 직접/AI 등록 진입, 사진 부분 실패 재시도, 완료 예약의 재고 확인. 1366px/320px 모두 통과.
- 최종 달력 320/390/1440px 캡처 및 다음 달→이전 달 이동 통과. 모바일 월 이동 버튼 한 행, 날짜 셀 높이 60px(데스크톱 72px).
- 수정한 SellerViews.jsx oxlint 통과.

1366×600 승인 화면 제목 y312→141, 버튼 y518→347. 390×844 사진 실패 제목 y277→98. 1366×600 등록방법 카드 CTA y558→514. 공통 shell/footer 개선은 별도 담당자가 반영했으므로 문서 전체 높이 변화에는 그 효과도 포함된다.

## 파일

- `before-*.png`, `after-*.png`: 실제 viewport 캡처. 달력 before 2장은 해당 달력 수정 직전 캡처.
- `before-geometry.json`, `after-geometry.json`: 위치·문서 높이·넘침 기록.
- `click-results.json`, `calendar-results.json`: 실제 클릭 및 최종 달력 결과.
- `capture.cjs`, `click-check.cjs`, `calendar-check.cjs`: 재현 스크립트.

프로덕션 수정 범위: `src/prototype/pages/seller.css`, `src/react/pages/seller/SellerViews.jsx`.
