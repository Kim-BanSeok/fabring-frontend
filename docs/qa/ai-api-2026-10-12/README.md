# 판매자 AI 보조 등록 API 연동

2026-10-12 · 계약 검토 기준 `7dc28c79994295daee635524d05048574247a6d9`

기존 판매자 원단 등록 화면에 API17~21의 대화 세션을 연결했습니다. [연결 현황의 M5](../../INTEGRATION_STATUS.md#core-work)에 해당합니다. 전체 테스트318개·lint·build, 실제 HTTP95항목·live adapter20항목·격리 오류12항목과 브라우저 확인 후 읽기 전용31항목을 통과했습니다. 사용자 요청에 따라 로컬 외부 AI 키·제공자 설정을 추가하지 않고 저장소의 개발용 규칙 제공자와 격리된 대체 검증을 사용했습니다. 실제 서버 API의 연결·검증과 외부 AI 모델의 응답 품질 검증은 구분합니다. 아래의 계약 검토는 실행 통과 수에 포함하지 않습니다.

## 연결 계약

| API | 요청 | 응답과 처리 |
| --- | --- | --- |
| 17 시작 | `POST /ai-sessions` | 본문 없이 세션 번호·첫 질문·초안을 받음. 승인된 판매자와 매장 필요 |
| 18 조회 | `GET /ai-sessions/{sessionId}` | 본인 세션의 대화 기록·현재 질문·미확인 항목·확정 원단 번호 |
| 19 답변 | `POST /ai-sessions/{sessionId}/answers` | `answer` 또는 `selected`, 대화 마무리는 `finish: true` |
| 20 확정 | `POST /ai-sessions/{sessionId}/confirm` | 직접 등록9와 같은 최종 원단 입력. 원단 번호와 `PENDING` 반환 |
| 21 중단 | `POST /ai-sessions/{sessionId}/abort` | `ABORTED`와 기존 초안·미확인 항목 반환. 이후 답변·확정 불가 |

모든 경로는 `/api/v1` 아래이며 SELLER 인증이 필요합니다. 세션 번호는 소문자16진수24자입니다. 시작·확정에는 판매자 승인과 매장을 다시 검사하며 다른 판매자의 세션은403입니다. 존재하지 않거나 보관 기간이 지난 세션은404입니다. 확정·중단한 세션의 다시 처리 요청은409 `AI_SESSION_CLOSED`입니다.

서버가 판매 형태 → 이름 → 크기 → 소재 → 두께 → 색상 → 하자 → 가격 순서로 현재 질문을 정합니다. 선택 답변은 AI 호출 없이 해당 값으로 처리하며 자유 입력은 현재 질문의 필드만 추출합니다. 사진을 분석하거나 한 번의 설명에서 모든 원단 정보를 만드는 API는 아닙니다. 답변은 최대1,000자이고 선택 답변과 자유 입력을 동시에 보내지 않습니다.

## 초안과 판매자 확인

`is_complete: true`는 추가 질문이 없다는 뜻이며 최종 등록 조건을 충족했다는 보장은 아닙니다. 판매자가 일찍 마무리하거나 모른다고 답하면 비어 있는 값이 남을 수 있습니다. 소재 미확인은 서버에서 `UNKNOWN`으로 표시하지만 두께·색상에는 미확인 enum이 없습니다. 이를 기본 두께·임의 색상으로 채우지 않고 판매자가 선택하게 합니다. 확인하지 않은 하자 여부도 하자 없음으로 확정하지 않습니다.

롤 길이는 cm로 정리하며1마는90cm입니다. 자투리 세로 길이가30cm 미만이면 같은 크기 질문을 다시 받고90cm를 넘으면 롤로 바꿀지 묻습니다. 롤로 바꾸면 자투리 길이를 지우고 남은 길이를 다시 확인합니다. 최종 자투리는30~90cm, 롤은 남은 길이90cm 이상이어야 합니다. 초안 수정·최종 확인 후 확정20으로 저장하고, 반환된 원단 번호에 기존 사진15~16 처리와 실패 복구를 연결합니다. 사진 없는 원단의 게시 승인은 차단되는 기존 계약을 유지합니다.

## 응답 유실과 직접 입력 전환

답변·확정·중단 POST 전후의 상태와 사용자 입력을 별도로 보존합니다. 응답 유실은 처리 실패의 증거가 아니므로 동일 요청을 자동 재전송하지 않습니다. 성공 응답을 받은 뒤 조회가 실패한 경우도 원래 쓰기 실패로 바꾸지 않습니다.

- 답변 결과를 못 받으면 현재 대화 기록·초안·다음 질문을 조회합니다. 같은 답변을 다음 질문에 잘못 적용하는 재전송을 피합니다.
- 확정 결과를 못 받으면 세션의 `CONFIRMED`와 `fabric_id`를 조회하여 기존 원단에서 사진 처리를 이어갑니다. 원단 생성9로 바로 우회하지 않습니다.
- 직접 입력으로 전환하기 전에 중단21의 `ABORTED` 결과를 확인합니다. 확정 요청과 경합해409가 오면 조회18로 원단 생성 여부를 먼저 확인합니다.
- 시작17의 응답에서 세션 번호를 받지 못했을 때 기존 세션을 찾는 목록 API는 없습니다. 새 대화를 시작하면 이전 빈 세션이 남을 수 있지만 시작만으로 원단을 만든 것은 아닙니다.

백엔드의 잠금은 한 서버 프로세스 내의 세션별 POST 순서만 보장합니다. 조회18은 잠금에 참여하지 않아 처리 중인 POST의 완료 이전 상태를 볼 수 있습니다. 조회의 `IN_PROGRESS`만으로 이전 요청이 실패했다고 판단하지 않습니다. 여러 서버나 재시작·응답 유실까지 보장하는 영속 멱등성 계약은 아닙니다.

## AI 제공자와 배포 전 남은 검증

백엔드는 `fake`와 `openai` 제공자를 지원합니다. `fake`는 키워드 규칙을 사용하는 개발·시험용 제공자이며 운영 모드에서는 허용되지 않습니다. 이번에는 로컬 키·제공자 설정을 추가하지 않는 사용자 요청을 반영하여 기존 `fake`와 오류·지연 대체 검증으로 마무리합니다. 실제 모델의 호출·추출 정확도·비용은 추후 설정된 환경에서 확인하며, 이번 결과를 외부 AI 품질 검증으로 보고하지 않습니다. 비밀키는 프론트 환경변수나 저장소에 넣지 않습니다.

브라우저 검증에서 개발용 가격 추출기가 `1마당 5500원`을 첫 숫자인1원으로 정리하는 한계를 확인했습니다. 프론트는 서버 초안을 임의로 바꾸지 않고 보여 주며 판매자가 최종 확인 폼에서5,500원으로 바로잡습니다. 이는 해당 규칙 제공자의 해석 한계이고 외부 모델에서 같은 문장을 정확히 처리했다고 검증한 것은 아닙니다. 대화 초안을 검토 없이 확정하지 않아야 하는 구체적인 사례로 남깁니다.

API 명세에는 MongoDB 세션 저장이 적혀 있지만 현재 서버 DAO는 메모리만 지원합니다. 진행·중단 세션은 마지막 갱신24시간 뒤 정리되고 확정 세션도 서버 재시작 시 사라집니다. 이미 생성된 원단·사진은 별도 PostgreSQL·이미지 저장소에 남습니다. 세션 영속화·재시작 복구·초안/최종본 보존은 팀이 사용할 환경의 후속 확인 사항입니다. [후속 협의](../../API_FOLLOWUPS.md)의 등록 시간·게시 후 비공개·이력 공백도 이 연결 작업으로 해소되지는 않습니다.

주 서버는 기존 `fake-rules` 제공자와 PostgreSQL을 그대로 사용했습니다. 원단159는 실제 HTTP로 자투리 확정과 사진 업로드를 마친 `PENDING`,160은 동시 확정 두 요청 중201과409가 한 번씩 반환된 단일 롤 원단입니다. adapter로 만든162는 실제 사진 업로드→관리자 승인→공개 `POSTED` 조회까지 확인했습니다.163은 AI 중단 뒤 기존 직접 등록 API로 만든 자투리입니다. 최초 검증 스크립트의 잘못된 조회 함수 사용으로161이 남았으며, 스크립트를 고친 뒤 별도 원단으로 재실행했습니다. 앱 결함이나 중복 요청으로 만든 원단은 아닙니다.

오류 검증은 별도 임시 loopback 포트에서 실행한 Express에 제공자 결과와 전송 응답을 제어했습니다. 주 서버를 재시작하거나 AI 제공자를 바꾸지 않았습니다. 선택 답변은 제공자를 호출하지 않았고 두 번의 추출 실패는 실제503 `AI_UNAVAILABLE`을 반환하면서 기존 초안·대화·질문을 유지했습니다.16,023ms 걸린 제어 답변도 AI 요청의45초 제한 안에서 성공했습니다. 타임아웃 뒤 자동 재전송 없이 조회하여 처리된 답변을 찾았고, 확정 성공 응답을 의도적으로 유실시킨 뒤 조회로 같은 원단164를 복구했습니다. 이후 중단409도 동일 원단 조회로 이어졌습니다.

새 검증 계정·원단·사진만 추가했으며 브라우저 확인 후 최종 읽기 전용 검증에서도 기존11개 모델의 행 해시가 동일했습니다. 공개 증거에는 비밀번호·토큰·개인 연락처·DB 접속 정보·외부 AI 비밀키를 포함하지 않습니다. 워크스페이스의 검증 스크립트·DB 실행 도구·테스트 자격증명은 이 프론트 저장소에 포함하지 않습니다.

## 실제 React 브라우저 확인

판매자 계정으로 대화를 시작하여 이름과 치수·소재·두께·색상·하자·가격을 입력했습니다. `폭 150cm 3마`는 폭150cm·잔량270cm로 정리됐습니다. 개발용 가격 추출 결과1원을 직접5,500원으로 수정하고 내용을 검토한 뒤 원단165를 확정했습니다. 원단은 `PENDING`, 폭150cm·잔량270cm·가격5,500원·사진1장으로 저장됐습니다. 새로고침 후 완성된 대화 이력을 조회했고 확정 세션에 다시 들어가도 같은 원단165를 안내하며 새 확정 요청을 보내지 않았습니다.

자투리 대화를 일찍 마무리하면 치수·가격·두께·색상 등이 비어 있고 하자 있음/없음 라디오도 어느 쪽도 선택되지 않습니다. 하자 여부를 선택하지 않으면 브라우저 필수 입력 검사에서 제출이 차단됐습니다. 판매자가 제목·폭80cm·길이60cm·가격2,500원·얇음·흰색을 보완하고 대화를 중단한 뒤 직접 입력으로 이동했을 때 그 값들이 유지됐습니다. 이 확인에서는 원단을 추가로 만들지 않았습니다.

390×844px에서 문서 폭은390px로 가로 넘침이 없었고, 채팅은 높이288px 안에서 전체654px 이력을 스크롤할 수 있었습니다. 마지막 콘솔 조회의 오류·경고는 모두0건입니다. 실물 모바일 기기·전체 화면의 스크린리더 검사나 실제 외부 AI 품질 검증을 수행한 것으로 확대하지 않습니다.
