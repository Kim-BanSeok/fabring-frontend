# 실제 API 연결 현황과 남은 작업

2026-10-12 · 백엔드 계약 기준 `7dc28c79994295daee635524d05048574247a6d9`

이 문서는 화면 제작 수가 아니라 **실제 계정·서버 데이터로 끝까지 동작하는 기능 묶음**을 셉니다. 판매자 원단 관리 연결과 로컬 검증을 마쳤습니다. 남은 핵심 연결은 **4묶음**, 통합 검증·배포/시연 환경 마무리는 **1묶음 별도**입니다. 묶음마다 구현·검증량이 달라 이 숫자를 완료 퍼센트나 남은 날짜로 환산하지 않습니다.

시연 화면이 존재하거나 서버 라우트가 구현됐다는 사실만으로 프론트 연결 완료로 세지 않습니다. [핵심 작업](#core-work), [선택 추가 범위](#optional-work), [계약·정책 확인](#decisions)을 구분합니다.

<a id="core-work"></a>
## 남은 핵심 연결 4묶음

번호는 완료 수를 셀 때 사용하는 고정 단위입니다. API 번호는 [명세 v0.3][api] 기준입니다.

| 번호 | 상태 | 기능 묶음 | 서버 계약과 이번 이후의 완료 기준 |
| --- | --- | --- | --- |
| M1 | **완료** | 판매자 직접 원단 관리·사진 | 9·11~16: 내 목록·상세, 자투리/롤 직접 등록, 수정·삭제, 실제 파일 업로드·삭제와 실패 복구. 생성 후 PENDING·반려 보완·활성 예약 삭제 제한까지 검증. [QA 기록](qa/seller-fabric-api-2026-10-12/README.md) |
| M2 | 대기 | 매장 등록·수정 | 5~7: 신규 판매자 매장 등록과 기존 매장 수정. 가입→매장 입력→승인 대기→등록 진입이 실제 계정으로 이어져야 함. 현재 내 매장 조회6만 연결됨 |
| M3 | 대기 | 관리자 판매자·원단 관리 | 33~38: 실제 목록·상세 데이터·페이지, 판매자 승인/거절, 원단 게시 승인/반려와 사유. 화면의 예시 통계를 실제 조회로 교체. 게시 후 비공개 계약은 아래 별도 확인 대상 |
| M4 | 대기 | 원단 기반 도안 추천·도안 조회 | 22~24: 실제 도안과 원단을 비교한 적합/확인 필요/결과 없음·판정 근거·롤 필요 길이/가격을 표시하고 예약 입력으로 연결. 현재 고정 파우치 계산은 참고 예시 |
| M5 | 대기 | 판매자 AI 보조 등록 | 17~21: 세션 시작·조회·질문 답변·확정·중단, 초안 수정, 미확인 값, 실패 시 기존 값 유지와 직접 입력 전환. 직접 등록·사진 흐름 재사용. **요구사항 P0이므로 선택 확장으로 제외하지 않음** |

서버에는 위 묶음의 기본 라우트가 있습니다. 새 API를 모두 만들어야 하는 상태는 아니지만, 다음의 P0 계약 공백은 기존 라우트 연결만으로 해소되지 않습니다: 등록 시간 기록(FAB-13), 게시 중 원단 비공개(ADMIN-02). 자세한 범위는 [계약·정책 확인](#decisions)에 둡니다.

다음 작업 순서는 **M2 → M3 → M4 → M5**입니다. 완성된 원단·사진 기반에 신규 판매자부터 승인·공개·예약까지 이어지는 흐름을 연결한 뒤 추천·AI를 붙입니다. AI 모델·세션 저장 정책처럼 결정이 필요한 항목은 구현 순서와 별개로 먼저 협의할 수 있습니다.

<a id="release-work"></a>
## 통합 검증·배포/시연 마무리 1묶음

M1~M5 이후 실제 구매자·판매자·관리자 계정으로 가입/매장→판매자 승인→원단 등록/사진→게시 승인→탐색/추천→예약→수락/수령/취소를 함께 확인합니다. 모바일, 권한, 재고 경합, 연결 실패, 입력 보존, 새로고침·재로그인, 시연 모드 회귀를 검증합니다.

배포 API 주소·HTTPS/CORS·이미지 저장 주소·서버 환경변수·AI 제공자 설정을 맞추고 시연용 데이터·실행 가이드·장애 대비 자료를 준비합니다. 현재 로컬 검증 완료를 배포 검증 완료로 세지 않습니다. 번들 크기 경고와 10,000건 달력 상한 등 알려진 제한도 최종 환경에서 점검합니다. 결제·배송·정산은 추가하지 않습니다.

## 선택 추가 범위 4개 후보

이 표는 위 핵심 작업과 별개입니다. 아래를 모두 P1이라고 부르거나 반드시 구현해야 하는4묶음으로 합산하지 않습니다.

| 후보 | 현재 상태와 기존 계약 | 범위 판단 |
| --- | --- | --- |
| E1 문의 작성·목록·답변 | 42~45 서버 구현. 프론트는 문의 건수만 실제 조회하며 원단별 문의/판매자 받은 문의·답변은 미연동 | 현재 화면을 실제화하는 추가 연결. 전체 원단에 걸친 구매자 본인 문의 목록과46·47 수정/삭제는 계약·구현 확인 필요 |
| E2 개인 프로필 수정 | 4 `PATCH /users/me` 구현, 구매자·판매자 닉네임/전화 수정은 미연동 | 현재 화면의 추가 연결. 매장 등록/수정 M2와 분리하며 이메일·비밀번호 변경까지 포함하지 않음 |
| E3 관심 저장 | 39~41 서버 구현, live 연결 없음 | 요구사항 정의서 §12의 **P1**. 저장/삭제/목록 UI와 기존 경로의 범위를 먼저 정함 |
| E4 지도·공장/부자재 정보 | 48 `GET /factories` 구현, 화면은 부자재 지도 예시 | **조건부 후보**. 공장등록자료를 검증된 부자재 소매점으로 바꾸어 표시하지 않음. 요구사항 §12의 제외 범위인 지역 제작업체 연결과 충돌하는지도 팀에서 정함 |

웹 알림·제작 사례·운영팀 AI 초안/최종본 비교는 요구사항상 P1이지만 현재 남은 화면 연결4후보에 자동으로 추가하지 않습니다. 새 화면·서버 범위를 확정하면 별도 작업 묶음으로 잡습니다.

<a id="decisions"></a>
## 계약·정책 확인이 남은 항목

아래 항목은 모두 새 화면을 추가하라는 요청이 아닙니다. 기존 요구사항과 서버 계약의 차이 또는 실서비스 전 결정 사항이며, 기능 묶음과 중복해 개수를 더하지 않습니다.

- **P0 등록 시간(FAB-13):** 직접 입력과 AI의 시작~확정 시간 기록을 요구하지만 v0.3 직접 등록 입력에는 등록 방식·시작/완료 시각이 없습니다. 프론트 검증 기록·서버 필드 복원·요구사항 조정 중 팀 결정을 해야 합니다.
- **P0 게시 후 비공개(ADMIN-02):** 현재 원단 승인/반려는 PENDING에서만 가능합니다. POSTED를 숨기는 별도 상태/처리와 진행 예약 영향이 정해지지 않았습니다. 관리자 화면 연결만으로 충족했다고 보고하지 않습니다.
- **AI 실행과 이력:** 서버는 fake/openai 제공자를 구분하며 현재 세션 저장소는 메모리입니다. 실제 AI 검증·모델/비용·재시작 시 세션 유실·질문/초안/최종본 보존 범위를 확정합니다. mock 제공자 테스트를 실제 AI 호출 검증으로 세지 않습니다.
- **예약 이력·연락처:** 자투리 금액·치수·당시 원단/매장 스냅샷, 구매자 연락처와 예약별 연락처는 [B1·B3](API_FOLLOWUPS.md) 협의가 남습니다.
- **등록과 사진 복구:** 생성/업로드 응답 불명과 완료 기준은 [B2](API_FOLLOWUPS.md). 일부 사진 성공을 전체 등록 완료로 오인하지 않으며 DRAFT/submit/멱등성 키가 이미 있다고 가정하지 않습니다.
- **부가 조회·운영 정책:** 본인 문의 전체 목록·문의 수정/삭제, 관리자 구매자 조회/추가 검색·통계, 공장/부자재 대상, 이메일·비밀번호 변경은 [B4](API_FOLLOWUPS.md)에서 구분합니다.
- **약관·개인정보 문안:** 화면의 약관 자료는 아직 pending입니다. 팀이 확정한 문안을 반영해야 하며 화면에서 임의 작성하지 않습니다.
