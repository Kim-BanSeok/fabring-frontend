# 후속 API 협의 사항

2026-10-11 Figma·API 비교 문서에서 프론트 인수인계에 필요한 B1~B4를 옮긴 요약입니다. 아래 필드와 URL 제안은 확정된 서버 계약이 아닙니다. 실제 구현은 [백엔드 API 명세 v0.3](https://github.com/goduckTeam/backEnd/blob/main/docs/API_%EB%AA%85%EC%84%B8%EC%84%9C_v0.3.md)과 해당 시점의 서버 소스를 함께 확인합니다. 프론트 인증 통합 검증 기준은 백엔드 `e177ea6`입니다.

## B1. 예약 이력에 표시할 원단 정보와 금액

예약 당시 원단명·치수·단가·표시금액을 어떻게 보존할지 확정해야 합니다. 자투리 예약의 `estimated_price`가 null이고, 판매 완료·삭제 이후에는 원단 상세 재조회만으로 과거 표시 정보를 복원할 수 없습니다.

- 예약 목록·상세에서 필요한 원단 요약과 가격 이력 필드를 합의합니다.
- 원단 가격 변경·판매 종료 후에도 예약 화면의 확정된 표시 정보가 유지되는지 확인합니다.
- 시연 데이터의 `display_price`, `fabric_title` 등을 서버 응답에 존재하는 필드로 간주하지 않습니다.

## B2. 원단 생성과 사진 업로드의 실패 복구

원단 생성 후 받은 `fabricId`로 사진을 별도 업로드하는 계약입니다. 일부 사진 실패 시 같은 원단의 실패한 사진만 재시도하고, 원단 생성 요청을 다시 보내지 않습니다.

- 생성 요청은 처리됐지만 응답을 받지 못한 경우의 중복 방지 정책을 합의합니다. 프론트 버튼 잠금만으로 서버 중복 생성을 막을 수는 없습니다.
- 사진이 일부만 올라간 PENDING 원단의 재개·정리와 관리자 노출 기준을 확인합니다.
- 서버 DRAFT·submit·멱등성 키는 현재 확정된 기능으로 약속하지 않습니다.

## B3. 예약 연락처의 의미와 노출 범위

예약 생성 계약에는 예약별 이름·전화번호 입력이 없습니다. 화면이 계정 정보를 확인하는 것인지, 별도 예약 연락처를 저장하는 것인지 팀에서 결정해야 합니다.

- 별도 저장이 필요하면 필수 여부·계정 값과 다른 경우·판매자에게 노출할 시점을 합의합니다.
- 계약이 정해지기 전에는 화면 입력만으로 예약 연락처가 저장되거나 전달됐다고 안내하지 않습니다.

## B4. 부가 화면과 기능의 범위

- 구매자 본인 문의 목록: 현재 원단별 문의·판매자 받은 문의와 구분하여 목록 계약을 확인합니다. `GET /inquiries/me`는 제안 경로입니다.
- 관리자 구매자 조회·통계·상태 외 검색: 필요한 데이터와 서버 필터·집계 계약을 확정합니다. 내려받은 한 페이지의 결과를 전체 검색·통계로 표시하지 않습니다.
- 부자재 지도: 실제 업체 데이터·좌표 제공 주체와 조회 계약이 정해질 때까지 예시임을 유지합니다.
- 이메일·비밀번호 변경: 전용 API·재인증·기존 토큰 처리 계약이 필요하며 현재 보류 화면을 임의로 복원하지 않습니다.

현재 화면 구현과 API 연결 범위는 [README](../README.md), 연결 순서는 [React 개발 기준](REACT_MIGRATION.md)에 정리되어 있습니다. 담당자·구현 일정과 최종 계약은 팀 합의 후 이 문서에 반영합니다.
